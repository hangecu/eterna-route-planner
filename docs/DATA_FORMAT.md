# Формат данных планировщика

События отделены от программной логики. Для исправления условия или последствия обычно достаточно изменить файл соответствующей главы в каталоге `data/events/`; файл `js/app.js` трогать не требуется.

Данные записаны как обычные объекты JavaScript, чтобы приложение могло запускаться двойным щелчком по `index.html`. Загрузка JSON через `fetch` при открытии с `file://` блокируется многими браузерами.

## Где что находится

- `data/events/chapter-1.js` … `chapter-5.js` — события, варианты выбора, условия и последствия;
- `data/choice-systems.js` — повторяемые наборы решений, например ежегодные дела и поездки;
- `data/state-catalogue.js` — названия и типы характеристик, отношений, статусов, достижений и финалов;
- `data/initial-state.js` — начальные значения и правила группировки;
- `data/planner-data.js` — небольшая точка сборки перечисленных файлов.

## Глава и событие

Упрощённый пример:

```js
{
  number: 1,
  id: "chapter-1",
  title: "Название главы",
  scenes: [
    {
      id: "scene-1-1",
      title: "Название события",
      type: "scene",
      choices: []
    }
  ]
}
```

События пересчитываются в том порядке, в котором записаны в массиве `scenes`. Для события, условия которого повторно проверяются после следующих решений, используется пометка `recurring: true`.

Если одно и то же повторно проверяемое событие может впервые появиться в разных главах, его копии получают одинаковый `occurrenceKey`. После первого появления общий ключ считается использованным во всех следующих главах.

Совпадение названия само по себе не означает, что события одинаковы. Отдельные версии получают разные `occurrenceKey`; общий ключ назначается только после проверки, что в главах повторно подключена одна и та же сцена.

Если у одного события есть отличающиеся версии, но произойти оно всё равно может только один раз, версии связываются одинаковым `onceKey`. Поле `locationVariant` добавляет понятную пометку `eterna` или `journey` и не участвует в проверке условий.

Поле `showLocationChange: false` скрывает смену местоположения в карточке, не меняя её влияния на расчёт.

Поля `scene-N-M` и `state-NNNN` связывают события с состояниями внутри планировщика.

Пометка `auxiliary: true` обозначает созданное для расчёта вспомогательное условие. Такие связи не показываются как отдельные последствия; местоположение выводится только при фактической смене между Этерной и поездкой.

## Выбор

```js
{
  number: 1,
  text: "Название выбора",
  requirements: [],
  effects: []
}
```

- `number` — порядок варианта в карточке;
- `text` — название, видимое игроку;
- `requirements` — блоки условий;
- `effects` — наблюдаемые механические последствия.

Каждый элемент `requirements` является одним обязательным блоком. Все условия внутри `conditions` должны выполняться одновременно. Массивы внутри `anyOf` задают альтернативы «или». Названия групп в интерфейсе не выводятся.

## Условия

Числовое условие:

```js
{
  type: "stat",
  parameter: { key: "state-0001" },
  operator: ">=",
  value: 6
}
```

Условие состояния персонажа:

```js
{
  type: "character-status",
  character: { key: "state-0002" },
  status: { key: "state-0003" },
  operator: "!="
}
```

Поддерживаемые операторы: `=`, `!=`, `>`, `<`, `>=`, `<=`.

## Последствия

Изменение характеристики:

```js
{
  type: "stat",
  parameter: { key: "state-0001" },
  value: 1
}
```

Изменение отношений с дополнительным справочным статусом:

```js
{
  type: "character",
  character: { key: "state-0002" },
  value: 1,
  status: { key: "state-0003" }
}
```

Поле `status` в таком последствии описывает состояние, связанное с результатом выбора. Само по себе его наличие не означает отдельного изменения постоянного статуса; интерфейс не должен изображать такое изменение без соответствующего эффекта.

Основные типы последствий:

- `stat` — числовая характеристика;
- `axis` — сторона двустороннего параметра;
- `relation` или `character` — отношение с персонажем;
- `status` — состояние персонажа;
- `flag` — достижение или наблюдаемое сюжетное состояние;
- `faction` — показатель сословия;
- `article` — решение статьи Кредо;
- `ending` — финал.

## Проверка после изменения

Из корня проекта выполните:

```text
node scripts/validate-project.mjs
```

Скрипт проверяет синтаксис и загрузку данных, уникальность событий, ссылки на состояния и автономную работу приложения.

Он также проверяет, что английская локаль полностью покрывает события, варианты и видимые состояния и содержит только разрешённые текстовые поля.
