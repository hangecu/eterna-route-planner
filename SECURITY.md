# Безопасность

Планировщик является статическим веб-приложением. Он работает на GitHub Pages или локально из ZIP и не требует установки, собственного сервера, учётной записи или доступа к папке игры.

## Что делает приложение

- загружает только собственные статические файлы страницы;
- хранит выбранный маршрут, состояние шапки и язык интерфейса в `localStorage` браузера;
- по команде пользователя создаёт локальный JSON-файл маршрута или TXT-памятку через стандартный браузерный `Blob`;
- читает JSON маршрута только после явного выбора файла пользователем и проверяет его формат до применения;
- по явному клику открывает локализованную страницу добровольной поддержки на Tribute в новой вкладке;
- изменяет только собственные данные в хранилище страницы.

## Чего в проекте нет

- исполняемых файлов `.exe`, установщика и фоновой службы;
- фоновых сетевых запросов, аналитики, рекламы и удалённого кода;
- внешних JavaScript-библиотек, шрифтов или изображений;
- автоматического чтения файлов пользователя, игры, сохранений, буфера обмена, cookies или системных каталогов.

В `index.html` задана Content Security Policy. Она разрешает загрузку собственных файлов страницы, но запрещает обращения приложения к API, внешние скрипты, объекты и отправку форм. Ссылка поддержки выполняет только обычный переход после клика. Автоматическая проверка контролирует структуру публичных файлов и локальные ссылки, а также запрещает сетевые API и любые внешние URL приложения, кроме двух страниц Tribute.

## Самостоятельная проверка

1. Убедитесь, что архив получен со страницы Releases проекта.
2. Сравните SHA-256 архива со значением в описании релиза.
3. Просмотрите `index.html`: он подключает только перечисленные локальные файлы.
4. Выполните `node scripts/validate-project.mjs`, если установлен Node.js.
5. Для обычного использования Node.js не нужен — достаточно открыть `index.html`.

Файлы в `data/` имеют расширение `.js` только ради автономного запуска через `file://`. Браузер исполняет их как локальные скрипты, поэтому не заменяйте их файлами из непроверенных источников. В официальной версии они содержат только присваивание декларативных объектов.

## Сообщить о проблеме

Не публикуйте сведения об уязвимости в обычном Issue до исправления. Используйте приватное сообщение через раздел **Security → Report a vulnerability** репозитория GitHub, если он включён. Для обычных ошибок в условиях и последствиях используйте Issue.
